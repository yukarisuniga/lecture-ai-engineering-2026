## 宿題

- 取り組んだレベル：実装
- 使ったモデル：gemini-3.5-flash-lite（既定）
- やったこと：
  - `app/ask.py` に `--chat` オプションを追加し、会話履歴を保ったまま続けて質問できるようにした
  - `client.chats.create(model=MODEL)` でチャットを作り、`chat.send_message()` で送る。チャットが送受信の履歴を保持し、毎回履歴ごとモデルに送るので、前の発言を踏まえて答えられる
  - `exit` / `quit` / `終了` または Ctrl+D で終了。空行は無視。API エラー（429 など）が出ても会話は終了せず続けられる
  - 各応答のあとに入力・出力トークン数と履歴の往復数を表示する（演習の TODO も `format_usage()` で実装）
  - `tests/test_ask.py` を追加。偽のクライアントで履歴が保たれることを確認（API キー不要）
- 結果：
  - `uv run pytest -q` で 13 件すべて通った
  - 実行例（`uv run python -m app.ask --chat`）：
    - 1回目「私の名前はユカリです」→「ユカリさん、はじめまして！どうぞよろしくお願いします。」
    - 2回目「私の名前は何ですか？」→「あなたの名前は「ユカリ」さんです。先ほど教えていただきましたよ！」。履歴があるので、前の発言を覚えて正しく答えられた
  - 入力トークン数の変化：1回目 7 → 2回目 58（出力は 44 → 16）
- 気づき・疑問：
  - 2回目の質問自体は短いのに、入力トークン数が 7 から 58 に増えた。1回目の質問とモデルの返答（44 トークン）が履歴として一緒に送られているためで、往復が増えるほど入力トークン数が増えていく。長く話すほどコストやレート制限に効いてくる
  - 会話が長くなったときに、古い履歴を削ったり要約したりする必要がありそうだと感じた
